# 에이전트 작업 루프

에이전트는 작업물을 넘기기 전에 1차 검토와 검증을 끝냅니다. 완료 보고 뒤에는 사용자가 결과를 검토하고 2차 확인 및 커밋·배포 여부를 결정할 수 있도록 인계합니다.

## 코드 작업

1. 작업 트리, 프로젝트 지침, 관련 문서와 호출부를 읽고 요청을 확인 가능한 완료 조건으로 정리합니다.
2. 기존 테스트와 재현 절차를 확인합니다. 회귀가 생길 수 있는 동작은 재현 테스트를 추가하거나 기존 테스트를 보강합니다.
3. 필요한 최소 변경을 구현합니다.
4. `pnpm verify`를 실행합니다. 변경한 UI 흐름은 브라우저에서 직접 확인할 수 있으면 그 확인도 합니다.
5. 실패 원인을 분류합니다. 이번 변경으로 생긴 실패는 수정하고, 다시 검증합니다. 기존 실패는 작업 전 상태와 비교하고 별도 문제로 기록합니다.
6. 변경 diff를 독립적으로 다시 읽고 요구사항, 경계 입력, 오류 처리, 접근성, 생성 파일과 부작용을 확인합니다.
7. 자체 검토에서 발견한 이번 변경의 문제를 수정하고 관련 검증을 다시 실행합니다. 변경분이 검토와 검증을 통과할 때까지 반복합니다.
8. 완료 보고에는 변경 파일, 실제 실행한 검사와 결과, 미해결 위험, 사용자가 2차 확인할 핵심 흐름을 적습니다.
9. 보고 후에는 사용자가 직접 결과를 확인하고 다음 결정을 내릴 수 있도록 작업을 멈춥니다. 커밋·푸시·배포는 명시적으로 요청된 경우에만 수행합니다.

## 코드 리뷰

1. `serene-harness/review-checklist.md`에 따라 요청 범위와 구체적인 결함을 확인합니다.
2. 리뷰 요청은 읽기 전용으로 진행합니다. 재현 가능한 발견 사항, 근거, 영향, 권장 조치와 실행한 검증을 보고합니다.
3. 사용자가 수정도 요청했다면 코드 작업 루프로 전환해 수정하고, `pnpm verify`와 관련 수동 검증을 통과한 뒤 재리뷰합니다.
4. 최종 보고에는 확인한 범위, 발견 사항 또는 수정 결과, 미해결 사항, 검증 결과를 구분해 적습니다.
5. 보고 후에는 사용자가 2차 검토와 커밋·배포 결정을 할 수 있도록 멈춥니다.

## 실패와 제한

- 검증이 실패하면 실패 지점의 로그와 관련 파일을 확인합니다. 실패를 숨기거나 검증 명령을 임의로 약화하지 않습니다.
- 네트워크, 비밀값, 외부 서비스, 권한 문제로 실행할 수 없는 검사는 이를 명시하고, 나머지 독립 검증을 계속합니다.
- `pnpm verify`의 빌드는 장소 카탈로그와 `docs/TRAVEL_PLACE_REVIEW.md`를 재생성합니다. 재생성 결과는 diff를 확인하고 요청 범위에 맞춰 반영합니다.
- 전체 `pnpm format:check`는 현재 레거시 포맷 불일치가 있어 기본 `verify`에 포함하지 않습니다. 새로 수정한 파일의 포맷은 가능한 좁은 범위에서 별도 확인하고, 기존 불일치는 무관한 변경으로 일괄 수정하지 않습니다.
- 완료를 막는 동일한 실패가 있으면 재시도만 반복하지 않습니다. 원인을 특정하고 안전한 대체 검증을 수행한 뒤, 필요한 사용자 결정 또는 환경 변경을 보고합니다.
