# 서울 여행 장소 선정 기준 v1

## 목적과 이번 단계의 범위

서울 열린데이터광장의 관광 명소 원천을 모두 지도에 표시하지 않고, **여행자가 볼거리·먹거리·체험·쇼핑을 목적으로 방문할 수 있는 장소**를 별도로 선정합니다. 관광 목적으로 방문할 쇼핑 명소도 포함합니다.

지도·검색·상세 화면은 선정 데이터셋의 369개 장소만 사용합니다. 보류 항목을 재검토해 특화 쇼핑 장소 9곳을 추가하고, 지원 서비스·일반 업종·복합 시설 중복 등 20곳을 제외했습니다. 좌표가 불명확하거나 휴관·운영 상태를 확인할 수 없는 18곳은 계속 보류합니다. 기존 43개 카탈로그에서 정확히 매칭된 14개 장소의 번역과 URL 별칭은 검토 원장에 통합했습니다. 기존 카탈로그는 런타임이나 재생성 과정에서 사용하지 않습니다.

## 포함 기준

| 카테고리   | 방문 목적                  | 포함 예시                                                    |
| ---------- | -------------------------- | ------------------------------------------------------------ |
| Culture    | 역사·건축·전시·문화 관람   | 궁궐, 박물관, 미술관, 문화 거리, 특색 있는 도서관            |
| Nature     | 산책·정원·경관 감상        | 공원, 정원, 산책길, 전망·야경 지점                           |
| Food       | 직접 먹고 마시는 방문      | 식당, 베이커리, 간식 가게, 음식 골목, 가맥·주점              |
| Cafe       | 커피·차·북카페 이용        | 카페, 다방, 전통 찻집                                        |
| Shopping   | 여행 목적의 쇼핑·문화 구경 | 관광 상권, 복합 쇼핑 공간, 전통공예점, 특색 있는 서점·음반점 |
| Experience | 체험·공연·관광 활동        | 공예 체험, 공연장, 관광 유람선, 케이블카                     |

한 장소에는 방문의 주목적에 따라 대표 카테고리 하나를 부여합니다. 미술관에 카페가 있어도 주목적이 전시 관람이면 Culture입니다. 백화점도 포함 가능한 유형이지만 단순히 백화점이라는 이유로 자동 포함하지 않습니다. 원천에 없는 장소를 새로 만들어 추가하지 않습니다.

## 제외와 보류

- **제외:** 물품보관소·관광안내소, 일반 역·대중교통 서비스, 치료·세탁·수선 등 일상 서비스, 방문 장소가 아닌 기획 기사, 동일 장소의 중복 원천.
- **추가 확인:** 일반 소매점과 관광 쇼핑 공간의 경계가 모호한 곳, 행사 때만 방문 가능한 공간, 기관 전체와 부속 시설의 중복 가능성, 원천 주소와 안내의 충돌, 휴관·임시휴업·관람 중단, 불명확한 위치.
- ‘오래가게’, ‘미래유산’, 주변 관광지 이름이 태그에 있다는 사실만으로 포함하지 않습니다. 일반 슈퍼·양복점·사진관을 카페거리·명소 태그 때문에 관광지로 판단하지 않습니다.
- 같은 좌표라도 독립된 관람·이용 목적이 있으면 유지합니다. 같은 장소를 소개한 별도 게시물은 `duplicateOf`로 대표 원천 ID에 연결합니다. 이름이나 좌표 일치만으로 자동 병합하지 않습니다.
- 추가 확인 항목은 삭제하지 않고 후보 데이터셋에서 보류합니다. 제외는 장소가 존재하지 않거나 가치가 없다는 뜻이 아닙니다.

## AI 판단과 사실 확인의 구분

2026-10-19 Codex 대화에서 한국어 원천 501건의 이름·태그·주소·운영 안내를 읽고 의미 기반으로 적합성을 검토했습니다. 기존 지오코딩 스크립트의 정규식 카테고리를 그대로 사용하지 않았습니다. 분류에는 판단 오류가 있을 수 있어 수정 가능한 검토 원장을 보존합니다.

`include`는 **여행 방문 목적에 맞는다는 판단**이며 현재 영업·개방·안전·인기도의 보증이 아닙니다. 전체 501건을 웹으로 전수 검증하지 않았습니다. 각 항목의 `evidenceFields`는 읽은 원천 필드이며 독립된 외부 검증 근거가 아닙니다. 별도로 확인한 공식 페이지는 `evidenceUrls`에만 기록합니다. 외부 페이지의 문구가 AI 실행 지시로 사용되지 않도록 자료로만 취급했습니다.

- 국립한글박물관: [공식 홈페이지](https://hangeul.go.kr/)의 전체 공간 공사·휴관 안내를 확인해 보류했습니다.
- 63 스카이피크닉: [공식 안내](https://63skypicnic.com/?locale=ko)에서 전망·미디어아트 공간임을 확인했습니다.
- 퐁피두센터 한화: [공식 미술관 소개](https://www.centrepompidou-hanwha.kr/about-us/museum_v1)를 확인했습니다.
- 감사의 정원: [서울시 안내](https://www.seoul.go.kr/news/news_report.do?nttNo=458538)를 확인했습니다.

`operatingStatus: unverified`는 현재 개방 여부를 외부 확인하지 않았다는 뜻입니다. `official_information_found`도 실시간 영업 보증은 아닙니다. 휴관을 확인한 항목은 `temporarily_closed`로 보류합니다. 원천의 영업 안내·재개관 예정일은 확인 당시 자료로 취급합니다.

## 데이터 파일과 재생성

1. `src/data/seoul-open-attractions.json`: 다국어 원천 2,481건과 출처·수집일. 원본 보존.
2. `src/data/seoul-travel-place-review.json`: 한국어 501건의 AI 판단 원장. `sourceId`, 원천 지문, 판단, 카테고리, 장소 유형, 근거, 검토일, 외부 근거를 보존.
3. `src/data/seoul-public-attraction-coordinates.json`: 기존 지오코딩 결과. 카테고리는 사용하지 않고 좌표와 이름·주소를 대조. 원천 주소에서 서울 밖 지역이 확인되면 제외하며, 서울 주소인데 좌표만 확정되지 않은 경우는 보류.
4. `src/data/seoul-travel-places.json`: 포함 판단을 받고 좌표 검사를 통과한 지도 입력. `seoul-attraction-{sourceId}`를 안정적인 ID로 사용. 출처·라이선스·수집일은 최상위 `source`에 보존.
5. `docs/TRAVEL_PLACE_REVIEW.md`: 포함·보류·제외 전 항목을 사람이 읽을 수 있는 검토표.

```sh
pnpm build:travel-places
pnpm test:travel-places
```

빌더는 AI API를 호출하지 않습니다. 현재 대화에서 작성한 판단 원장을 검증하고 재현 가능한 선정 파일과 검토표를 생성합니다. 생성 파일을 직접 수정하지 않고 판단 원장을 수정한 뒤 재생성합니다.

원천을 갱신할 때는 기존 `sync:seoul-attractions` → `geocode:seoul-attractions` → `build:travel-places` 순서로 실행합니다. 신규 항목이나 이름·태그·주소·운영 안내·공식 링크·교통 안내가 바뀐 항목은 **자동 포함하지 않고 재검토**합니다. `inputFingerprint`는 이 필드들의 SHA-256 지문입니다. 수집 시각만 바뀌면 기존 판단은 유지됩니다. 삭제된 원천은 출력에서 빠지고 검토 ID는 `retiredReviewIds`에 남습니다.

좌표는 이름·주소가 현재 원천과 일치하고 서울 자치구·대략적 서울 범위 안에 있는 주소 검색 결과만 사용합니다. 키워드 검색 좌표와 미해결 좌표는 보류합니다. 이는 명백한 오류를 걸러내는 검사이며, 건물 입구나 안전한 관람 지점의 정확성을 검증한 것은 아닙니다.

## 지도 연결

`src/data/spots.ts`는 선정 데이터셋만 지도용 장소로 변환합니다. `src/data/publicAttractions.ts`도 같은 파일에서 운영·교통 정보를 조회합니다. 기존 상세 URL 별칭은 검토 원장의 `legacyId` 필드로 유지하며 해당 장소가 선정 목록에 남아 있을 때만 연결됩니다. Shopping·Experience 필터를 포함한 여섯 카테고리와 모든 장소의 상세 페이지가 같은 장소 카탈로그를 사용합니다.

기존 상세 URL은 공공 원천 ID가 선정 목록에 남아 있는 경우에만 연결합니다. 예전 장소 목록을 새 목록에 합산하지 않습니다. 상세 화면에는 공식 안내 링크와 데이터 출처·라이선스·수집일을 표시합니다. `pnpm build`는 선정 데이터셋을 재생성한 뒤 빌드하므로 신규·변경된 원천이 검토 없이 배포되지 않습니다.
