# 변경 리뷰 체크리스트

변경분과 관련된 항목만 확인합니다. 해당되지 않는 항목은 생략합니다.

## 리뷰 절차

1. 사용자가 지정한 범위를 확인합니다. 범위가 없으면 작업 중 변경분을 기준으로 하고, 대상이 모호할 때만 짧게 확인합니다.
2. 프로젝트 프로필과 관련 규칙, 알려진 기존 문제를 읽습니다. 이번 변경으로 새로 생기거나 악화된 부분에 집중합니다.
3. 변경 diff와 필요한 호출부를 확인합니다. 자동 생성 파일은 프로젝트에서 리뷰 대상으로 정한 경우에만 포함합니다.
4. 관련 자동 검사 결과를 참고하되, 이미 도구가 보고한 내용을 사람이 찾은 결함처럼 중복 나열하지 않습니다. 실행하지 않은 검사는 실행한 것처럼 보고하지 않습니다.
5. 리뷰는 읽기 전용으로 수행합니다. 발견 사항은 문제 상황, 영향, 근거와 권장 조치를 보고하고 별도 요청 없이 파일을 고치지 않습니다.
6. 검증 명령을 실행했다면 실제 실행 여부와 결과를 기록하고, 자동 검사가 이미 보고한 내용을 중복 지적하지 않습니다.
7. 사용자가 리뷰와 수정을 함께 요청한 경우에는 발견 사항을 수정한 뒤 코드 작업 검증 루프를 완료하고 최종 결과를 보고합니다.

## 동작과 회귀

- [ ] 요구사항과 실제 동작이 맞고 경계값·빈 값·실패 경로를 고려했는가?
- [ ] 호출부, API 계약, 저장 데이터, 사용자 흐름에 미치는 영향을 확인했는가?
- [ ] 비동기 경합, 재시도, 중복 제출, 취소가 문제가 될 수 있는가?

## 프론트엔드

- [ ] 로딩·오류·빈 상태와 폼 검증이 기존 패턴과 일관적인가?
- [ ] 키보드 조작, 라벨, 포커스, 반응형 레이아웃을 고려했는가?
- [ ] 서버 상태와 화면 상태를 구분하고 캐시 무효화를 올바르게 했는가?

## 백엔드

- [ ] 인증·인가를 서버에서 검증하며 입력과 권한 경계를 확인했는가?
- [ ] DB 변경의 원자성, 인덱스, 동시성, 롤백·배포 순서를 검토했는가?
- [ ] 오류 응답, 로그, 재시도 동작에 민감 정보가 노출되지 않는가?

## 운영과 유지보수

- [ ] 생성 파일과 원본 정의를 구분하고 올바른 생성 절차를 따랐는가?
- [ ] 의존성·환경변수·설정 변경이 필요한 최소 범위인가?
- [ ] 검증 결과가 실제 실행 여부와 일치하며 미실행 검사를 명시했는가?

## 보고 형식

리뷰는 동료와 함께 살펴보는 어조로, 근거와 대안을 담아 터미널에서 읽기 쉬운 Markdown으로 작성합니다. 강압적으로 지시하지 않고 선택적 개선은 제안으로 구분합니다. 다음 순서를 사용합니다.

1. **좋았던 점**: 변경에서 잘 처리한 부분을 구체적으로 짚습니다.
2. **요약**: 발견 건수와 가장 중요한 결론을 적습니다.
3. **발견 사항**: 심각도별로 묶고, 각 항목에 파일·라인, 재현 가능한 영향, 권장 조치를 적습니다.
4. **확인 범위**: 읽은 변경 범위와 실행한 검사, 미실행 검사를 구분합니다.

심각도는 사용자가 받는 영향에 맞춰 `Critical`, `Major`, `Minor`, `Suggestion`으로 구분합니다. 실제 결함과 취향성 제안을 섞지 않습니다. 발견 사항이 없으면 없다고 명시하고, 좋은 점과 확인 범위를 보고합니다. 기존 기술 부채는 새로 악화되었거나 이번 변경이 직접 건드린 경우에만 지적합니다. 리뷰 요청에서는 발견 사항과 확인 범위를 보고합니다. 구현 요청에서는 전체 리뷰 보고서를 만들지 말고 완료 보고 형식을 사용합니다.

| 등급         | 기준                                                      |
| ------------ | --------------------------------------------------------- |
| `Critical`   | 보안 취약점, 데이터 손실, 서비스 중단, 명백한 치명적 버그 |
| `Major`      | 정상 사용을 막는 버그, 계약 위반, 큰 회귀·유지보수 위험   |
| `Minor`      | 제한된 조건에서의 문제, 작은 컨벤션·가독성 결함           |
| `Suggestion` | 동작상 결함은 아니지만 선택적으로 고려할 개선             |

각 발견 사항은 **제목과 등급, 파일·라인, 문제 상황, 영향 근거, 권장 조치**를 포함합니다. 확신이 낮은 추정은 사실처럼 단정하지 말고 확인 필요로 표시합니다.

리뷰 결과는 기본적으로 대화 응답에 출력합니다. 사용자가 요청하지 않은 리뷰 보고서 파일은 만들지 않습니다.
